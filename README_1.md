# 하루결

하루의 결을 따라가는 개인용 업무·컨디션 관리 도구.
혼자 쓰려고 만든 거라 배포·서명·계정 없음.

만든 이유: 업무를 자주 놓치고 일정을 까먹어서, 하루를 시간 블록으로
나눠 부하를 분산하고, 업무를 잘게 쪼개 보관하고, 그날의 컨디션을
기록으로 남겨 나중에 패턴을 눈으로 확인하려고.

---

## 핵심 개념

- **주요 업무 보관함** — 떠오른 업무를 시간대 고민 없이 일단 던져두는 곳.
  여기서 각 블록으로 배치한다. 비어 있지 않아도 괜찮음(못 옮긴 게 남는 게 정상).
- **4블록** — 아침 / 점심 / 저녁 / 밤. 블록 아래에 체크리스트로 업무를 쪼갠다.
- **상태 마킹** — 하루를 한 단어로: 해냄 / 즐거움 / 가라앉음 / 무너짐.
  하루 하나만 고른다(패턴이 선명하게 보이라고).
- **지난 흐름** — 최근 2주의 상태를 색 막대로. 기억이 아니라 기록으로 곡선을 본다.
- **하루 경계** — 자정(00:00) 기준. 자정 넘긴 입력은 다음 날로 친다(예외 처리 없음).

---

## 파일

- `하루결.html` — 앱 본체. 순수 HTML/CSS/JS, 외부 라이브러리 없음.
  데이터는 브라우저 localStorage 키 `harukyul.v2`에 저장.

> 이 HTML 하나가 폰(PWA)과 노트북(Electron) 양쪽의 공통 자산.
> HTML을 손보면 양쪽에 그대로 재사용된다.

---

## 지금 쓰는 법 (가장 단순)

1. `하루결.html`을 브라우저로 연다.
2. 끝. 데이터는 그 브라우저에 저장된다.

⚠️ 브라우저 캐시/데이터를 지우면 날아간다. 가끔 **내보내기**(JSON)로 백업할 것.
(내보내기/가져오기 버튼은 1단계 PWA 작업에서 추가 예정)

## 로드맵

순서대로. **하나가 일상에 자리 잡은 걸 확인한 다음 다음으로 넘어간다.**
동시에 여러 개 떠안지 말 것 — 도구 만들다 부하 늘리면 본말전도.

### 1-B. 노트북 (Windows / Electron) — **먼저 이것부터**
바탕화면 스티커 메모처럼 상주하는 데스크톱 앱.
- 항상 위(always on top), frameless 작은 창, 시작 시 자동 실행, 트레이 토글
- 저장은 로컬 JSON 파일 → OneDrive 폴더에 두면 노트북 간 자동 백업
- 기존 HTML/CSS/JS를 렌더러로 그대로 재사용
- 빌드: npm 기반, portable .exe 수준이면 충분

**MVP 먼저**: 창에 하루결이 뜨는 것까지가 1차 목표.
always-on-top·자동시작 등은 그 다음에 하나씩 켠다.

### 1-A. 폰 (Android / PWA)
홈 화면에 설치하는 앱.
- manifest + 서비스워커로 오프라인 동작
- 상단 "오늘 남은 핵심" 요약(미완료 3~4개, 넘으면 스크롤) — 알림 대신 ambient 표시
- JSON 내보내기/가져오기
- 가능하면 안드로이드 홈 화면 위젯(기기/크롬 버전 따라 지원 갈림)

### 2단계. 기기 간 동기화 (후순위)
폰·노트북 자동 동기화. Supabase(매직링크 로그인, days/inbox 테이블,
last-write-wins). 여건 될 때. 그 전까진 JSON 수동 + OneDrive로 충분.

## 환경

- 폰: Android + Chrome
- 노트북: Windows, Node/npm 설치돼 있음(없으면 nodejs.org에서 설치)

## 데이터 구조 (참고)

localStorage 키 `harukyul.v2`:

```
{
  "days": {
    "2026-06-30": {
      "state": "good" | "joy" | "low" | "break" | null,
      "tasks": {
        "dawn":  [ { "id", "txt", "done" }, ... ],
        "noon":  [ ... ],
        "dusk":  [ ... ],
        "night": [ ... ]
      }
    }
  },
  "inbox": [ { "id", "txt" }, ... ]
}
```

Electron으로 옮길 때 이 구조를 그대로 JSON 파일로 저장한다.

## 막히기 쉬운 지점 (미래의 나에게)

- **Electron frameless 창이 안 움직임** → 상단바에 `-webkit-app-region: drag`,
  그 안의 버튼엔 `no-drag`.
- **fs 접근이 안 됨** → preload + contextBridge 경로 확인.
  nodeIntegration 끄고 contextIsolation 켠 표준 구조.
- **OneDrive 충돌 사본 생김** → 노트북 두 대에서 동시에 열지 말 것.
  저장은 임시파일에 쓰고 교체(atomic write).

## 원칙

이건 **일을 줄이려고** 만든 도구다.
- 완벽하게 채우려 하지 않는다. 비는 칸이 있어도 된다.
- 보관함에 남은 게 보여도 죄책감 갖지 않는다 — 못 끝낸 목록이 아니라
  머리에서 꺼내 안전하게 둔 곳이다.
- 만드는 과정이 또 다른 과부하가 되면 멈춘다. MVP에서 끊어도 된다.
